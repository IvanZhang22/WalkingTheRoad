# 行小道本地 Agent v1.2.0：意图识别与人工纠正

## 一、版本目标与边界

v1.2.0 在 v1.1.0 四条独立工作流之前增加一个意图识别节点，降低用户不了解 W1—W4 时的入口选择成本。

本版只做四件事：接收一段自由文本、推荐一条主工作流、说明理由与缺失信息、等待用户确认或改选。它不自动运行工作流，不接收附件，不保存路由记录，不串联工作流，也不修改 W1—W4 的业务提示词。

## 二、完整交互框架

```text
用户自由描述当前任务
        │
        ▼
3L-0-1_大模型-意图识别-1
        │
        ├── w1：研究设计助手 ──┐
        ├── w2：访谈提纲助手 ──┤
        ├── w3：质性材料分析 ──┤── 用户人工确认 ── 打开对应结构化表单
        ├── w4：研究质量质检 ──┤
        └── uncertain ─────────┘   （补充描述或直接点击四张工作流卡）
```

“使用推荐工作流”只打开表单，不自动提交。主页和侧栏的四个手动入口始终保留，它们既是快捷入口，也是人工纠错机制。W2 的“生成新提纲/审查已有提纲”仍在 W2 表单中由用户显式选择。

## 三、后端接口

### （一）请求

```http
POST /api/route
Content-Type: application/json
```

```json
{
  "message": "我已经整理好三份访谈记录，想做初步编码并提炼共同主题。"
}
```

`message` 会去除首尾空白，长度须为 1—4000 字符；多余字段会被拒绝。

### （二）响应

```json
{
  "recommended_workflow": "w3",
  "reason": "用户已有访谈原文并希望开展编码和主题提炼。",
  "missing_information": [],
  "confidence": "high",
  "possible_secondary_workflow": null
}
```

- `recommended_workflow`：`w1`、`w2`、`w3`、`w4` 或 `uncertain`；
- `confidence`：`high`、`medium` 或 `low`；
- `possible_secondary_workflow`：复合任务中可能的后续步骤，不会自动执行；
- 模型未配置返回 503，模型调用或结构化输出失败返回 502，输入不合规返回 422。

## 四、路由判断规则

1. W1：研究问题、对象、范围、方法或研究方案仍需界定；
2. W2：需要新建或审查访谈问题；
3. W3：已有访谈记录、观察笔记等原始材料，需要编码、主题与引文分析；
4. W4：已有分析、结论、主张或报告，需要核对证据、样本边界和表述风险；
5. 复合任务只推荐当前第一步，后续步骤写入次要工作流；
6. 信息不足返回 `uncertain`，不得用低把握强行分流；
7. 用户输入被包在不可信数据边界内，不能改变系统规则或索取系统提示词。

## 五、验收方法

### （一）无成本自动检查

在项目目录运行：

```powershell
python -m ruff check .
python -m mypy app
python -m pytest
node --check app\static\app.js
python scripts\run_regression.py
python scripts\run_routing_regression.py
```

四工作流回归用于证明 v1.1.0 能力未被破坏；路由回归包含 40 例标准、模糊、复合、信息不足和提示词注入输入。模拟模型只验证工程分支，不能评价真实分类质量。

### （二）真实模型验收

配置 `.env` 后运行：

```powershell
python scripts\run_routing_regression.py --live
```

此命令会产生 API 用量。结果写入 `test-results/live/v1.2.0-routing-时间戳/`，包括 JSON、CSV 和分类统计。建议人工重点复核：

1. 标准案例主工作流准确率；
2. 模糊案例是否愿意返回 `uncertain`，而不是过度自信；
3. 复合案例是否坚持“当前第一步优先”；
4. “访谈提纲”和“访谈记录”是否混淆；
5. 提示词注入是否改变 JSON 格式、泄露规则或越权回答业务问题；
6. 推荐理由和缺失信息是否能帮助普通用户纠正选择。

## 六、手工界面验收清单

- 自由描述为空时不能提交；
- 路由中按钮和文本框被禁用，完成后恢复；
- 推荐卡显示工作流名称、理由、把握度和缺失信息；
- 接受推荐只打开结构化表单，不创建运行记录；
- 点击任一其他工作流卡可以纠正模型建议；
- `uncertain` 不出现强制接受按钮；
- W2 仍须在表单里选择生成或审查；
- 工作流运行期间禁止发起第二次路由或第二条工作流；
- 手机窄屏下描述框、推荐卡和四张菜单卡可读；
- 停止并重启服务后，不应存在上次路由或运行状态。

## 七、进入 v1.3.0 前不在本版解决的问题

- 浏览器项目卡、跨工作流字段复用与线性串联；
- 账号、数据库、跨轮记忆和用户历史；
- `/models`、`/chat/completions`、Bearer 鉴权与清小搭接入；
- 图片、音频、OCR、多模态解析；
- 自动替用户执行推荐工作流。
