# v2.2.4：多模态证据接入 W3

## 最小闭环

同一个 `POST /v1/chat/completions` 现在按以下顺序执行：

```text
清小搭附件 URL
  → 安全下载
  → 文档解析 / ASR / OCR
  → 片段级置信度与定位门控
  → W3 证据提取
  → 后端确定性引文核验
  → 主题生成
  → 同一个 Chat Completion 返回报告
```

没有新增第二个 Chat API，也不要求清小搭配置 MCP。纯文本消息仍只做原有工作流
路由；只有带附件、路由到 W3 且至少存在一个自动可用片段时，才自动执行完整 W3。

## 证据安全规则

1. 送入 W3 的输入由后端重新构造，只包含
   `automatic_evidence_use=true` 的片段；低置信、缺失置信度或缺失定位的正文不会进入
   提示词。
2. 每个输入片段带唯一 `source_segment_id`、材料 ID、模态、定位和厂商置信度。
3. 大模型必须把 `evidence.source_id` 填为 `source_segment_id`，且引文只能从同一片段
   连续复制。
4. 后端核验器不相信模型：它再次检查片段是否存在、引文是否在该片段中精确连续
   出现。跨片段拼接、错误编号和改写引文全部拒绝并清空。
5. 通过核验的证据由后端补写 `material_id`、`source_segment_id`、`location` 和
   `provider_confidence`，主题生成只能读取这份核验后对象。
6. 没有自动可用片段时返回“W3 未运行，请先人工复核”，不会用待复核内容生成正式
   主题。

## 清小搭请求

```json
{
  "model": "xingxiaodao-agent",
  "messages": [
    {
      "role": "user",
      "content": [
        {
          "type": "text",
          "text": "研究问题：学生为什么难以找到学校就业服务入口？请做质性材料分析。"
        },
        {
          "type": "input_audio",
          "input_audio": {
            "url": "https://<可公开下载的临时地址>/interview.mp3",
            "format": "mp3"
          }
        }
      ]
    }
  ]
}
```

请求头仍为：

```text
Authorization: Bearer <AGENT_API_KEY>
Content-Type: application/json
```

清小搭只传临时 URL，不传 base64，不把阶跃、百度或其他厂商密钥放进工作流。
