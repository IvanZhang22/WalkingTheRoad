# 行小道本地 Agent v1.3.0：浏览器项目卡与四工作流串联

## 一、版本目标

v1.3.0 让 W1—W4 围绕同一个社会实践项目连续工作，同时保留 v1.2 的临时单次运行方式。项目模式遵循三条硬规则：模型只能提出写回建议、用户确认后才保存、原始附件不进入浏览器项目卡。

## 二、完整数据流

```text
新建／导入项目
      │
      ▼
浏览器项目卡 localStorage
      │ 白名单项目摘要 + 表单输入 + 本次附件
      ▼
W1 / W2 / W3 / W4 原有工作流
      │
      ▼
3L-*-3_大模型-项目卡写回建议-3
      │ 严格 JSON、字段权限校验、失败安全降级
      ▼
逐字段差异与人工勾选
      │
      ├── 确认并进入下一步
      ├── 确认并返回项目总览
      ├── 修改本阶段并重跑
      └── 放弃写回
```

没有活动项目时，后端不会调用 `3L-*-3`，节点链、费用和结果操作保持 v1.2 行为。

## 三、项目卡 Schema 与容量

浏览器固定键为 `xingxiaodao.projects.v1`。项目包含：身份与修订号、研究问题、目标群体、背景、方法计划、访谈提纲、材料元数据、候选编码、主题、结论、质检结果、阶段状态、阶段输出快照及修订历史。

安全限制：

- 单个阶段 Markdown 最多 50,000 字符；
- 单项目最多约 1MB；
- 全部项目按约 4MB 的 UTF-16 安全预算控制；
- 修订历史最多保留最近 200 条；
- 被新运行替换的阶段 Markdown 最多保留最近 12 份；
- 材料最多 50 份，只保存编号、文件名、类型、背景、大小、字符数、SHA-256和摘要；
- 不保存文件正文、文件对象、API Key、节点提示词或完整调试轨迹。

存储不可用或写满时，页面会切换为内存临时模式并显示警告，不会谎称已经永久保存。

## 四、工作流字段权限

| 工作流 | 读取项目字段 | 允许建议写回 | 下一步 |
|---|---|---|---|
| W1 | 项目名、研究背景、目标群体 | 研究问题、目标群体、背景、方法计划、待解决事项 | W2 |
| W2 | 研究问题、目标群体、方法计划、已有提纲 | 访谈提纲、待解决事项 | W3 |
| W3 | 研究问题、最近材料卡 | 材料元数据、候选编码、主题、结论、待解决事项 | W4 |
| W4 | 研究问题、目标群体、候选结论、材料定位 | 质检状态、质检记录、待解决事项 | 无 |

后端再次校验工作流编号、阶段、下一工作流、重复字段和字段权限。W3 的材料元数据由后端根据真实上传文件计算并覆盖模型建议，防止模型伪造哈希或把原文塞入项目卡。

## 五、状态、回退与失效

标准阶段为：

```text
draft → w1_confirmed → w2_confirmed → w3_confirmed → w4_audited
```

项目同时维护 `confirmed_stages` 和 `stale_stages`，因此允许直接从 W2、W3 或 W4 开始。跳过上一阶段或使用过期上游时，表单要求用户显式勾选风险确认。

- W1 的研究问题、对象、背景或方法变化：已完成的 W2—W4 过期；
- W2 的访谈提纲变化：已完成的 W3—W4 过期；
- W3 的材料、编码、主题或结论变化：已完成的 W4 过期；
- 重新确认某阶段后，该阶段自身解除过期；
- 旧成果不删除，继续保留在阶段结果和修订历史中。

## 六、接口变化

`POST /api/runs` 新增可选 multipart 字段 `project_context_json`。它只接受 `ProjectContext` 白名单字段，最长 250,000 字符。未知字段、原始正文和错误 Schema 返回 400。

运行成功响应的 `RunRecord` 新增可选 `proposed_project_patch`。临时单次模式为 `null`；项目模式包含建议字段、理由、确认后阶段、下一工作流、缺失条件和降级警告。

## 七、无成本自动验收

```powershell
.\.venv\Scripts\python.exe -m ruff check .
.\.venv\Scripts\python.exe -m mypy app
.\.venv\Scripts\python.exe -m pytest
node --test tests\js\test_project_store.cjs
node --check app\static\app.js
node --check app\static\project-store.js
.\.venv\Scripts\python.exe scripts\run_regression.py
.\.venv\Scripts\python.exe scripts\run_routing_regression.py
.\.venv\Scripts\python.exe scripts\run_project_regression.py
```

Python 测试覆盖项目上下文白名单、写回越权、安全降级和原有工作流。Node 测试覆盖刷新恢复、四阶段确认、上游失效、修订冲突、材料过滤、导入副本和存储失败降级。

## 八、人工验收路径

1. 新建项目，填写研究背景，从 W1 开始运行；
2. 检查写回差异，取消至少一个字段，再确认进入 W2；
3. 验证 W2 表单只预填已确认字段；
4. 依次完成 W2、W3、W4，确认 W3/W4 每次都要求重新上传原始材料；
5. 刷新页面，确认项目、阶段和修订记录仍在；
6. 修改 W1 研究问题，确认已完成 W2—W4 显示为需要重新生成；
7. 新建第二项目并切换，确认两个项目不串字段；
8. 导出第一个项目，再导入，确认生成不同编号的副本；
9. 删除副本，确认没有误删原项目；
10. 切换临时单次模式，确认运行结果没有项目卡写回面板。

真实模型验收应重点审查写回节点是否保持事实边界、字段颗粒度是否适合复用、候选主题和结论是否被误写成确定事实。真实回归会产生 API 用量，不在默认测试中自动执行。

## 九、版本边界

本版不实现账号、数据库、跨设备同步、云端恢复、知识库、OCR、音频转写、多模态、OpenAI 兼容协议或清小搭接入。项目 JSON 是本地演示与迁移格式，不承诺作为未来数据库的永久 Schema。
