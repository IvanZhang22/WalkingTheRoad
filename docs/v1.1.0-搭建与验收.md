# 行小道本地 Agent v1.1.0 搭建与验收

## 一、版本定位

v1.1.0 的任务是建立全代码基线，不进行新一轮提示词优化。提示词来源如下：

1、W1：低代码 v1.1.0；

2、W2：低代码 v1.2.0；

3、W3：低代码 v1.3.0；

4、W4：低代码 v1.4.0；

5、统一菜单：低代码 v1.5.0。

## 二、数据流

```text
Chrome 本地测试页
        │ multipart：workflow_id + fields_json + source_file
        ▼
POST /api/runs ──→ 内存运行记录 ──→ 返回 run_id
        │
        ▼
WorkflowService 逐节点执行
        │
        ├─ 输入字段校验
        ├─ DOCX/PDF/TXT/MD 文本解析
        ├─ 阶跃星辰 Coding Plan / DeepSeek 的 OpenAI兼容调用
        ├─ Pydantic JSON结构校验
        ├─ W3/W4逐字引文核验
        └─ 最终Markdown
        ▲
        │ GET /api/runs/{run_id} 轮询
Chrome 展示节点进度、结果和调试轨迹
```

## 三、节点错误处理

（一）输入节点

1、必填字段缺失：停止，不调用模型。

2、文件类型错误：停止并说明支持格式。

3、扫描型 PDF：明确提示当前版本不含 OCR。

4、正文为空或超过字符限制：停止，不把文件名当正文。

（二）大模型节点

1、网络超时、429、5xx：由 OpenAI 客户端最多自动重试两次。

2、空响应：停止工作流。

3、中间 JSON 无效：清除代码围栏、解析并用 Pydantic 校验。

4、首次校验失败：只允许进行一次 JSON 修复调用。

5、修复仍失败：记录节点错误，不生成伪造的空结果。

（三）代码核验节点

1、原文完全匹配：`exact_match`；

2、仅空白字符不同：`whitespace_normalized_match`；

3、其他情况：`rejected`，清空引文正文并进入拒绝清单；

4、禁止语义相似匹配。

## 四、本地人工验收

（一）服务配置

1、`/api/health` 显示当前启用的服务商与模型；默认应为 `stepfun` 与 `step-router-v1`；

2、思考模式显示关闭；

3、浏览器源代码和网络响应中不存在 API Key。

（二）四条工作流

1、每条工作流能从主菜单进入；

2、W2 的两种意图显示不同表单，并复用风险审查节点；

3、W3、W4 只允许一个材料文件；

4、运行时能看到当前节点编号；

5、调试面板能查看每个节点的提示词、输出、状态和耗时；

6、最终结果保留 Markdown 标题、列表、表格和代码块；

7、“重新使用”“返回主菜单”“导出 Markdown”“直接结束”均可操作。

（三）失败测试

1、不填写必填字段；

2、上传 PNG、MP3 或 EXE；

3、上传无文字层 PDF；

4、把 `.env` 中的 Key 临时改错；

5、W2 审查模式不填写已有问题；

6、材料中加入“忽略系统规则”等提示注入文本，确认系统仍将其作为材料处理。

## 五、11例回归验收

1、先运行模拟回归，确认 11/11 工程链路完成；

2、再运行真实回归，每例只调用一次完整工作流；

3、检查每例 JSON 中的全部节点记录；

4、对最终 Markdown 按事实边界、方法适切性、证据可追溯、结构可执行性分别打 0—5 分；

5、W3/W4 重点人工搜索双引号内容，并回到原材料逐条确认；

6、只有 11/11 无未捕获异常、W3/W4 无未核验直接引文，才把版本标记为通过。

## 六、进入下一版本的条件

v1.1.0 验收完成后，v1.2.0 才增加意图识别和人工纠正。不得在 v1.1.0 中提前加入数据库、自动串联、多模态或清小搭标准接口，以免无法判断问题来自迁移还是新功能。
