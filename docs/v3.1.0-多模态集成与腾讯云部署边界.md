# v3.1.0：多模态集成与腾讯云部署边界

## 一、版本范围

v3.1.0 以 v3.0.0 的清小搭研究旅程为基础，合入 PR #11 的多模态代码：安全下载、文档解析、阶跃/Deepgram 音频转写、百度图片与扫描 PDF OCR、置信度和定位门控、W3 证据链。

保留的 v3.0.0 规则包括：可纠正路由、隐私授权、材料确认、人工确认、项目进度状态，以及不向用户暴露内部节点和协议措辞。

## 二、已验证

- 单一 `/v1/chat/completions` 入口兼容文本、`input_audio` 与 `file` URL 内容块；
- 128 项自动化测试连续两次通过；Ruff 与 Mypy 均通过；
- 未配置真实服务密钥时，音频和 OCR 保持失败关闭，不会用模拟内容冒充识别结果；
- 低置信度、缺少定位信息的片段不会自动进入 W3 证据链。

## 三、腾讯云生产边界

腾讯云正式服务保持 v3.0.0 的 `.env`，升级到本分支后默认仍关闭 ASR/OCR。真实启用前必须分别配置和验收：

- `ASR_PROVIDER=stepfun` 或 `deepgram`，以及对应的有效密钥；
- `OCR_PROVIDER=baidu`，以及有效的百度 OCR AK/SK；
- 清小搭实际下发的附件 URL、文件 MIME 类型和下载可达性。

PR #11 含有 Vercel Blob 浏览器大文件直传。这一层只适用于 Vercel Preview，腾讯云生产环境不配置 `BLOB_READ_WRITE_TOKEN`；后续应改为腾讯云 COS 的预签名上传。不能把“代码含有 Blob”表述为“腾讯云已支持大文件直传”。

## 四、部署顺序

1. 通过云服务器健康检查确认 v3.1.0 已启动；
2. 在清小搭分别实测文本、普通文档、音频、图片和扫描 PDF；
3. 将每类结果记录为成功、明确失败或待配置，不能以接口连通性替代真实能力验收；
4. 确认回滚路径有效后，再合并 v3.1.0 的 PR 到 `main`。
