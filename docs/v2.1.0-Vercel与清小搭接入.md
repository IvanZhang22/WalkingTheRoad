# 行小道 v2.1.0：Vercel 部署与清小搭接入

## 一、部署前提

v2.1.0 以 v2.0.0 的 OpenAI 兼容接口为唯一对外入口：

```text
GET  /v1/models
POST /v1/chat/completions
Authorization: Bearer <AGENT_API_KEY>
```

`AGENT_API_KEY` 是清小搭调用行小道的访问密钥；`MODEL_API_KEY` 是行小道调用阶跃星辰的模型密钥。两者必须不同，且都只在 Vercel 环境变量中保存。

部署前将 GitHub 仓库设为 Private。GitHub Free 支持私有仓库，Vercel 获得仓库授权后仍可部署。本版已从 `feat/v2-openai-compatible` 完成 Preview 验证；合入 `main` 后该分支删除。

## 二、Vercel 部署操作

1. 在 Vercel 用 GitHub 登录，导入 `IvanZhang22/WalkingTheRoad`，并选择 `feat/v2-openai-compatible` 创建 Preview；
2. Root Directory 保持仓库根目录；Framework Preset 选择 Other；
3. 在 Settings → Environment Variables 同时为 Production / Preview 配置：

```text
APP_MODE=live
MODEL_PROVIDER=stepfun
MODEL_API_KEY=<你的阶跃星辰密钥>
MODEL_BASE_URL=https://api.stepfun.com/step_plan/v1
MODEL_NAME=step-3.5-flash
MODEL_THINKING=disabled
MODEL_TIMEOUT_SECONDS=110
MAX_UPLOAD_MB=20
MAX_DOCUMENT_CHARS=300000
AGENT_API_KEY=<随机生成、仅供清小搭使用的新密钥>
```

4. 部署后记录 Vercel 域名，例如 `https://walking-the-road.vercel.app`；
5. 不要把任何真实密钥写回 `.env.example`、GitHub Issues、截图或清小搭公开描述。

使用 PowerShell 生成 32 字节随机 `AGENT_API_KEY`；输出直接粘贴到 Vercel，并保存到密码管理器，不发送给其他人：

```powershell
$keyBytes = New-Object byte[] 32
[System.Security.Cryptography.RandomNumberGenerator]::Fill($keyBytes)
[Convert]::ToHexString($keyBytes).ToLowerInvariant()
```

如果 Vercel 提供 Sensitive 选项，为两把 Key 开启。环境变量新增或修改后必须 Redeploy，已经生成的旧部署不会自动读取新值。

## 三、部署后自测

以下命令中的域名和密钥均替换为真实值；不要把执行记录发到公开群聊。

先访问 `/api/health`，必须确认：`status=ok`、`version=2.1.0`、`provider=stepfun`、`model=step-3.5-flash`、`key_configured=true`、`agent_key_configured=true`。该接口只暴露配置状态，不返回密钥。

```powershell
$baseUrl = 'https://你的域名.vercel.app'
$headers = @{ Authorization = 'Bearer <AGENT_API_KEY>' }
Invoke-RestMethod -Uri "$baseUrl/v1/models" -Headers $headers
```

```powershell
$body = @{
  model = 'xingxiaodao-agent'
  messages = @(@{ role = 'user'; content = '我有三份访谈记录，想做主题分析' })
} | ConvertTo-Json -Depth 5
Invoke-RestMethod -Method Post -Uri "$baseUrl/v1/chat/completions" `
  -Headers $headers -ContentType 'application/json' -Body $body
```

验收：`/v1/models` 返回 `object=list`；聊天返回 `object=chat.completion`，并建议 W3；错误密钥返回 401，不泄露实际密钥。

还要测试 `stream=true,max_tokens=1`：响应必须是 `text/event-stream`，依次包含 role、content、stop+usage，并以 `data: [DONE]` 结束。

## 四、清小搭接入

在清小搭选择“OpenAI 兼容协议 / 对端 Agent”接入时：

- Base URL 填写 `https://你的域名.vercel.app/v1`；
- API Key 填写 `AGENT_API_KEY` 的值；
- Model 填写 `xingxiaodao-agent`；
- 先完成连通性和最小消息探测，再测试普通文本与流式输出；
- v2.1.0 只声明文本能力。音频、文件 URL 输入和附件输出必须等 v2.2.0 真正验收后再勾选。

目标状态是清小搭的 connectivity、credential、minimalChat、responseFormat 四项全部通过，流式能力显示 verified。但本次测试在访问 `/v1/models` 时返回 `SocketException`，赛事答疑已说明清小搭不能连接境外服务器；该结果判定为部署地域阻塞，而非 OpenAI 协议失败。国内部署、正式试聊和提交审核顺延至 v2.3。

## 五、上线后观察与回滚

1. 用清小搭分别测试问候、W1、W2、W3、W4 四类文本意图；
2. 记录响应时间、HTTP 状态、流式 stop 帧和模型异常，不记录用户原文或密钥；
3. Vercel 环境是无状态的，不能依赖内存保存跨轮项目卡；
4. 故障时在 Vercel Deployments 选择上一稳定部署 Promote，或在 GitHub 回退到上一稳定标签；
5. 遇到密钥疑似泄露，先在 Vercel 和模型平台轮换密钥，再审查日志和 Git 历史。

Vercel Preview、模型列表、鉴权和真实聊天已经通过；清小搭因境外网络限制未通过。本版以该边界升级为 `2.1.0`、合入 `main` 并创建正式标签，不提交公共广场审核。v2.2 先整合多模态，v2.3 再部署国内云、完成清小搭试聊并提交审核。
