# 行小道 v2.2.1：文档安全接入

## 一、版本范围

本阶段只完成远程附件安全下载和普通文档解析，不接入音频 ASR、图片 OCR、扫描 PDF OCR、视频或 MCP。公开入口仍只有：

```text
POST /v1/chat/completions
Authorization: Bearer <AGENT_API_KEY>
```

支持的文档格式：TXT、Markdown、DOCX，以及具有足够文字层的 PDF。扫描 PDF 返回 `XDW-DOC-OCR-REQUIRED`，等待 v2.2.3 处理，不会把空文本交给 W3。

## 二、安全下载边界

`SafeDownloader` 使用异步 HTTP 客户端，并执行：

1. 只允许 HTTP/HTTPS，拒绝 URL 内嵌凭据；
2. 每一跳重定向前重新校验主机和 DNS；
3. 拒绝 localhost、`.internal`、私网、回环、链路本地、保留、组播和元数据 IP；
4. 在可取得实际连接地址时再次检查对端 IP；
5. 不读取系统代理环境变量，避免请求被未知代理改写；
6. 同时检查 `Content-Length` 和实际流式读取字节数；
7. 校验响应 MIME、文件扩展名和文件头；DOCX 还必须包含合法 Office ZIP 结构；
8. 每个附件使用独立临时文件，并由服务层在 `finally` 中删除；
9. `DownloadedFile` 不保存来源 URL，临时路径也不进入公开序列化。

DNS 校验不能替代部署层的出口网络策略。正式国内服务器仍应通过防火墙阻止访问云元数据和内网网段。

## 三、文档解析与定位

- TXT/Markdown：依次识别 UTF-8 BOM、显式 UTF-16 BOM 和 GB18030；
- DOCX：提取段落和表格行；
- PDF：按页提取文字层；
- 所有文字统一换行后保留完整 `normalized_text`；
- 文本片段记录全局 `char_start/char_end`；PDF 片段同时记录 `page`；
- 单片段最多 50,000 字，全文仍受 `MAX_DOCUMENT_CHARS` 限制；
- 全部片段可用时，`automatic_text` 与 `normalized_text` 完全一致，避免引文位置漂移。

## 四、环境变量

```text
MAX_UPLOAD_MB=20
MAX_DOCUMENT_CHARS=300000
MULTIMODAL_CONNECT_TIMEOUT_SECONDS=10
MULTIMODAL_READ_TIMEOUT_SECONDS=120
MULTIMODAL_MAX_REDIRECTS=3
```

本阶段没有新增厂商 API Key，也不会产生 ASR/OCR 调用费用。

## 五、失败隔离

一个附件下载或解析失败时，返回对应 `Material.issues`，其它附件继续处理。Live 环境当前只启用 `document`：音频和图片返回 `XDW-MM-PROVIDER-NOT-CONFIGURED`，不会调用 Mock Provider，也不会先下载未启用模态。
