# 行小道本地 Agent v1.4.0：GitHub协作、CI与发布基线

## 一、版本边界

v1.4.0 只解决工程能否安全入库、多人审查、自动回归、发布和回滚。它不改变 Agent 产品能力，不加入知识库、云部署、清小搭协议或多模态。

## 二、仓库边界

独立仓库根目录就是本 Agent 工程目录。只包含源码、空值配置样例、虚构测试材料、自动测试和必要文档。根目录的赛事说明、团队 Word/Excel、真实材料和其他成员工作目录一律不进入仓库。

`.env`、虚拟环境、缓存、运行结果、发布包、本地数据和上传目录由 `.gitignore` 排除；CI还会扫描被跟踪文件中的常见密钥、私钥、办公/音频附件和5MB以上文件。

## 三、质量门

本地和 GitHub Actions 共用：

```powershell
.\.venv\Scripts\python.exe scripts\run_quality_gate.py
```

依次验证仓库安全、Ruff、Mypy、35项Python测试、7项浏览器项目卡测试、两个前端脚本语法、11例四工作流回归、40例路由回归和4例项目写回回归。全部使用Mock，不产生模型费用。

## 四、分支与评审

`main`只接收通过PR的稳定成果。使用 `feat/`、`fix/`、`docs/`、`chore/` 分支。PR必须说明目标、主要变化、未改范围、测试结果、隐私核查、已知风险和回滚方法。

产品与学术内容由马俊博定调，资料和测试内容由岳承鑫整理，多模态模块由马仲琪负责，Agent主架构和版本验收由张一凡负责。涉及多领域时按马俊博、岳承鑫、马仲琪、张一凡的顺序呈现职责和意见。

## 五、发布

版本号同时存在于包、应用、健康接口、页面、README和CHANGELOG。向远端推送 `v1.4.0` 标签后，Release工作流先验证标签与包版本完全一致，再运行全部质量门，最后生成：

```text
xingxiaodao-agent-v1.4.0.zip
xingxiaodao-agent-v1.4.0.zip.sha256
```

发布包只使用 Git 跟踪文件，不含 `.env`、虚拟环境、运行结果或本地资料。

## 六、回滚

1. 不删除或移动已经发布的标签；
2. P0问题立即停止继续部署或演示对应版本；
3. 从上一稳定标签建立 `fix/` 分支；
4. 修复后完整运行质量门，发布补丁版本；
5. 如果只是赛事演示，明确切回上一稳定标签，不用未验证工作区覆盖；
6. 泄露密钥时先撤销密钥，再处理Git历史，不能只提交一次“删除密钥”。

## 七、验收标准

- 私库只含Agent工程和虚构夹具；
- PR失败时不能按团队规则合入main；
- 新电脑可克隆、配置空白 `.env` 并启动；
- `v1.4.0` 标签、Release、ZIP内部版本一致；
- 发布包安全扫描通过；
- 马仲琪至少能通过一个练习PR完成分支、提交、推送和评审闭环；
- v1.1—v1.3所有能力回归不下降。
