# v2.2.2：阶跃音频文件识别与证据安全边界

## 已实现

- 通过统一 `POST /v1/chat/completions` 接收 `input_audio`，没有新增第二套公开接口；
- 服务端安全下载并校验音频后，调用阶跃文件 ASR 的异步提交与查询接口；
- 请求固定开启 `show_utterances=true`，把官方分句的 `start_time/end_time` 保存为毫秒定位；
- 轮询有请求超时、总超时和节流，失败、空结果及缺时间戳全部失败关闭；
- API Key、附件 URL、URL 查询参数和厂商错误正文均不会进入公开响应；
- m4a、webm 暂不发送给阶跃文件 ASR，因为该官方接口当前只声明支持 wav、mp3、ogg、pcm。

官方依据：

- [阶跃音频文件识别](https://platform.stepfun.com/docs/zh/api-reference/audio/asr)
- [阶跃 HTTP/SSE 语音识别](https://platform.stepfun.com/docs/zh/api-reference/audio/asr-sse)

## 环境变量

```dotenv
ASR_PROVIDER=stepfun
STEPFUN_ASR_API_KEY=
STEPFUN_ASR_BASE_URL=https://api.stepfun.com/v1
STEPFUN_ASR_MODEL=step-asr-1.1
STEPFUN_ASR_REQUEST_TIMEOUT_SECONDS=30
STEPFUN_ASR_POLL_TIMEOUT_SECONDS=300
STEPFUN_ASR_POLL_INTERVAL_SECONDS=2
```

当 `MODEL_PROVIDER=stepfun` 且 `STEPFUN_ASR_API_KEY` 留空时，服务端复用
`MODEL_API_KEY`。如果主模型不是阶跃，必须单独配置 `STEPFUN_ASR_API_KEY`。
真实 Key 只放在本地 `.env` 或 Vercel 环境变量中，不得写入 Git、截图或清小搭提示词。
之前截图中出现过的 Key 必须先在阶跃控制台撤销并重新生成。

## 当前安全边界

阶跃文件 ASR 官方成功响应提供分句和时间戳，但没有声明分句置信度字段。因此本
Provider 不伪造置信度；这些片段会带 `confidence_missing` 标记并进入
`manual_review`，不会自动成为正式引文。后续可配置一个真实返回置信度的备用 ASR
Provider，或者增加明确的人工批准步骤后再进入 W3。
