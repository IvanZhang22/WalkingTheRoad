# v2.2.6：Vercel 大文件直传

## 问题

Vercel Function 请求体上限为 4.5 MB。旧网页把文件放在 `multipart/form-data` 中直接提交到 `/api/runs`，因此 18.9 MB MP3 在进入 Python 后端前就会返回 `413 FUNCTION_PAYLOAD_TOO_LARGE`。提高 `MAX_UPLOAD_MB` 或 `maxDuration` 都不能改变平台网关限制。

## 新链路

```text
≤ 4 MB：浏览器 → /api/runs multipart → 识别与证据链
> 4 MB：浏览器 → Vercel Public Blob → /api/runs 只传 URL → 识别与证据链 → 删除临时 Blob
```

大文件不会先经过 Function，也不会在浏览器压缩或转码，因此传给识别服务的仍是原始音频。默认业务上限为 100 MB，可通过 `MAX_UPLOAD_MB` 调整。Deepgram 预录音频官方上限为 2 GB，但本项目暂时使用更保守的 100 MB，控制上传滥用、识别耗时和费用。

## 部署配置

1. 打开 Vercel 项目的 `Storage`；
2. 创建或连接一个 **Public Blob Store**；
3. 将它连接到 Production，Vercel 会自动注入 `BLOB_READ_WRITE_TOKEN`；
4. 保留 `BLOB_CLEANUP_ENABLED=true`；
5. 将 `MAX_UPLOAD_MB` 设置为 `100`，重新部署；
6. 打开 `/api/health`，确认：

```json
{
  "large_upload_configured": true,
  "max_upload_mb": 100
}
```

网页选择超过 4 MB 的文件时会显示直传进度，上传结束后自动创建分析任务。

## 安全边界

- 上传令牌有效期 5 分钟；
- 令牌限制固定目录、扩展名、Content-Type 和最大尺寸；
- Blob 使用随机文件名，不允许覆盖；
- `/api/runs` 只接受行小道目录下的 Vercel Public Blob URL；
- 分析结束后无论成功或失败都会尝试删除 Blob；
- URL、Blob Token 和 Provider Key 都不会写入项目卡；
- 本项目当前没有用户账户认证，公开部署时应增加访问控制或限制受信任演示人员使用。

## 音频压缩建议

如果不配置 Blob，只能把文件压缩到约 3.8 MB 以下。语音识别不要求音乐级音质；单声道、16 kHz、MP3 48–64 kbps 通常能保持良好人声清晰度。32 kbps 在安静、近讲、单人录音中通常仍可用，但噪声、远距离、多人重叠或方言场景更容易降低准确率。不要使用 16 kbps 以下，也不要对已经低码率的 MP3 反复转码。
