# v2.2.3：图片与扫描 PDF OCR

## 已实现

- 图片继续走统一 `POST /v1/chat/completions` 的 `file` content part；
- PDF 优先读取原生文字层，文字层不足时只对该 PDF 回退到 OCR；
- 直接调用百度 PP-OCRv6 API，不增加 MCP 或第二个公开入口；
- 图片按文字行保存矩形 `bbox=(left, top, width, height)`；
- 扫描 PDF 逐页识别，同时保存 `page` 和 `bbox`；
- 读取接口返回的 `probability`，每行置信度进入统一证据门控；
- 低于 0.8、置信度缺失或 bbox 缺失的文字行只进入人工复核；
- Access Token 在内存中按有效期缓存，失效时只自动刷新一次；
- PDF 页数、百度表单编码后 4 MiB 限制、网络超时和单附件失败均失败关闭。

官方依据：

- [百度 PP-OCRv6](https://cloud.baidu.com/doc/OCR/s/6mncwkr9c)
- [百度 OCR 调用方式与 Access Token](https://cloud.baidu.com/doc/OCR/s/Ck3h7y2ia)
- [百度 OCR 接口说明（PDF 页码从 1 开始）](https://cloud.baidu.com/doc/OCR/s/gkibizxd5)

默认使用控制台可免费创建应用的 PP-OCRv6。百度当前文档规定其请求路径仍是
`/rest/2.0/ocr/v1/pp_ocrv5`；返回的 `lines`、`probability`、`rec_boxes` 会统一
映射到文字、置信度与矩形 bbox，不改变业务 Schema。

## 环境变量

```dotenv
OCR_PROVIDER=baidu
BAIDU_OCR_API_KEY=
BAIDU_OCR_SECRET_KEY=
BAIDU_OCR_BASE_URL=https://aip.baidubce.com
BAIDU_OCR_ENDPOINT_PATH=/rest/2.0/ocr/v1/pp_ocrv5
BAIDU_OCR_TIMEOUT_SECONDS=60
BAIDU_OCR_MAX_PAGES=20
```

必须同时配置 AK 和 SK 才会在 Live 模式开放图片 OCR。密钥只放本地 `.env` 或
部署平台环境变量，不放入 Git、清小搭提示词、工作流 JSON、截图或演示材料。

## 输入限制

- 公开契约当前接受 png、jpg、jpeg、webp 和 pdf；
- 百度接口要求 form-urlencoded 后的文件不超过 4 MiB；代码按实际编码后的请求
  大小检查，不能通过只看原文件大小绕过；
- 扫描 PDF 默认最多 20 页，避免误上传大型文件导致高延迟和不可控费用；
- 对外仍不接受视频。
